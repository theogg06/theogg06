A load misses in L1, L2 and L3, so the core allocates a line fill buffer and sends the request out to DRAM. The memory controller opens the row (tRCD) and reads the column (CL). The line then crosses the 64-bit channel as a burst of eight 8-byte beats. DDR4 orders the burst from the requested column: first the requested word, then the rest of its 32-byte half with wrap-around, then the other half. For byte 40 (word 5) the order is 5 6 7 4 1 2 3 0. The waiting load completes as soon as its own word lands, about 81 ns after issue. The rest of the line follows 2.5 ns later.

When all eight valid bits are set, the fill buffer writes the whole line into the set at once. Every load in this figure maps to set 44 of a 32 KiB, 8-way L1D (address bits 6–11), so each new line replaces the least recently used way. The evicted line is clean, so it is dropped rather than written back.

Times are typical for DDR4-3200 CL22 (tCK 0.625 ns, tRCD and CL 13.75 ns, 0.3125 ns per beat) behind a three-level cache; real latency varies with the core, the fabric and queueing. The figure slows the 81 ns of latency about 33 million times and the 2.5 ns burst about 1.6 billion times, so each beat can be followed.
